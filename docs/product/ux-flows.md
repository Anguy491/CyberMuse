## 视觉呈现规则

全部流程使用 [CyberMuse Signal UI](ui-design-system.md)。行为和状态以本文及 FR/NFR 为准，Signal UI 只决定呈现方式：dark/light 双主题、每屏三层/一个主焦点、留白优先、有限 signal red、工程化阶段、克制动效和可访问的文字/形状冗余。状态变化和错误必须就地显示 `[SAVED]`、`[LOADING]` 或 `[ERROR]`，不得使用会自动消失的 Toast。任何页面不得为追求 Nothing-inspired 外观而隐藏恢复动作、缩小 Pitch Lane、使用未审查/联网字体、使用 skeleton，或让颜色成为唯一状态编码。

## 信息架构

主导航包含 Library、Practice（仅在歌曲已打开时）、Review（仅在 session 已选择时）和 Audio Settings。Import 是从 Library 进入的任务流，不作为永久导航页。

全局状态：

- 顶部显示当前歌曲、后台分析状态和离线/模型状态。
- 长任务可最小化到 Library，但不能静默消失。
- 错误使用稳定错误码，并提供重试、打开设置、释放空间或查看诊断等明确动作。

## Flow 1 — 首次启动

1. 显示产品目的和本地优先说明。
2. 不在启动时请求麦克风，也不自动下载模型。
3. 空 Library 显示“导入歌曲”和“先测试麦克风”两个入口。
4. 用户进入 Import 时才说明模型需求；进入 Audio Settings 时才说明麦克风用途。

成功状态：用户知道数据保存在本机并能选择下一步。失败状态：配置损坏时使用安全默认值并显示可清除设置的提示，不阻塞 Library。

## Flow 2 — 导入与分析

1. 用户从 Library 选择“导入歌曲”。
2. 文件选择器只突出 MP3/WAV/FLAC；取消后回到原状态。
3. Import 显示文件名、格式、时长和预估本地空间，用户确认复制。
4. 如果模型缺失，展示名称、用途、大小、来源、许可证和“下载/取消”。取消保留歌曲为 `model_required`。
5. 分析页按 `probe → normalize → separate → pitch → postprocess → write` 显示阶段和总进度。
6. 用户可以取消；界面先显示 `cancelling`，完成清理后转为 `cancelled`，保留重试。
7. 成功后显示“开始练习”；失败显示错误原因、数据状态、重试和诊断入口。

状态集合：`selecting`、`validating`、`copying`、`model_required`、`queued`、`running`、`cancelling`、`cancelled`、`failed`、`ready`。

## Flow 3 — Library

每首歌曲列表项显示标题（默认来自文件名，后续可编辑）、时长、导入时间、分析状态、最近练习和本地占用；默认用留白和分隔线组织，不采用等权卡片网格。

- `ready`：主操作“练习”。
- `running`：显示阶段、进度、取消。
- `failed`：显示错误摘要、重试、删除。
- `model_required`：显示下载模型。
- `damaged`：显示缺失资产和删除/重新分析，不尝试静默修复。
- 空状态：说明支持格式、本地处理和首次分析可能较慢。

删除是破坏性操作：确认对话框列出将删除的原曲副本、派生文件和会话；成功后提供短暂的界面撤销仅在文件尚未实际清除时可用，否则不宣称可恢复。

## Flow 4 — Audio Settings

1. 页面先显示为什么需要麦克风及“请求权限”按钮。
2. 授权后列出输入设备、系统默认输出、实时电平和检测到的音高。
3. 用户选择设备后执行输入测试；设备静音、被占用或消失时显示恢复步骤。
4. 延迟校准解释将播放短促声音，建议使用耳机并把麦克风靠近耳机。
5. 有效测量显示 `latencyMs`、置信度和设备组合；失败不保存值，可重试或使用手动偏移。

权限拒绝不是致命错误：Library 和歌曲分析保持可用，Practice 可进入预览但“开始录唱”不可用。

## Flow 5 — Practice

进入条件：歌曲 `ready`，参考轨有效。页面结构：

- 顶部：歌曲、返回 Library、保存状态。
- 主区域：固定 NOW（位于可视宽度约 38%）、音高纵轴、向左移动的参考/用户轨。
- 即时反馈：目标音、当前音、signed cents、准确/偏高/偏低/未检测状态。
- 底部：播放/暂停、seek、麦克风、A-B Loop、时间、音量。

交互规则：

- 播放伴奏不自动开启麦克风；首次开启时使用已授权设备。
- 暂停冻结 NOW 和 session 时间；重新播放开始新的连续 segment。
- seek 清空跨越位置的平滑窗口，避免旧帧污染。
- 无声或低置信度显示中性状态，不判 Miss。
- 反馈等级需要滞回和时间平滑；轨迹仍可显示原始有效观察的轻量平滑版本。
- 麦克风断开时伴奏暂停，提示选择新设备或以预览模式继续。

## Flow 6 — A-B Loop

1. 用户在时间轴拖选或通过 A/B 按钮设置区间。
2. 合法区间必须在歌曲范围内且长度至少 1,000 ms。
3. 启用后，播放从 A 前 500 ms 预备位置开始；评分从 A 开始。
4. 到 B 时结束当前 take，短暂停顿 300 ms 后回到预备位置。
5. 页面显示 take 编号和最近三次指标；退出 loop 后保留区间但停止循环。

v0.1 不叠加无限条轨迹；只保存所有 take 数据，在 Practice 中最多显示参考、当前 take 和最近一次 take。

## Flow 7 — 结束与 Review

1. 用户选择“结束练习”或返回 Library。
2. 有有效观察时保存 session；无有效观察时询问丢弃还是保留空会话，不显示虚假分数。
3. Review 显示音准、median absolute error、signed median bias、稳定性、覆盖率。
4. 时间轴突出误差持续超过阈值的区间，摘要使用“整体偏低约 18 cents”等可解释语言。
5. 用户选择区间可“重新练习此处”，创建预填 A-B Loop 并返回 Practice。

## 全局异常与恢复

| 场景 | 用户数据状态 | 必须提供的动作 |
|---|---|---|
| 麦克风权限拒绝 | 歌曲与分析安全 | 打开系统设置、重试、预览歌曲 |
| 分析器崩溃 | 已有有效缓存安全 | 重试、删除临时数据、导出诊断 |
| 模型下载失败 | 歌曲副本安全 | 重试、检查网络、取消 |
| 磁盘不足 | 旧数据安全，新写入未提交 | 打开存储管理、选择删除缓存、重试 |
| 资产被外部删除 | 其他歌曲安全 | 重新分析或删除损坏歌曲 |
| session 保存失败 | 当前内存数据暂存到离开前 | 重试、导出诊断、确认放弃 |

错误页面和对话框不得暴露 traceback、内部临时路径或无法执行的建议。
